    Load a source to calculate a no-conversion recommendation.

    No conversion stream-copies compatible source audio into the M4B without changing codec, bitrate, sample rate, channels, or quality. It is fastest and avoids generational loss, but is recommended only when every source is AAC with matching sample rate and channel layout. Mixed bitrate alone is acceptable. Non-AAC or inconsistent sources should be converted for reliable M4B playback.

    Opus Transcode
    
        DEV · WIP
      
    
      
    Re-encodes audiobooks to Opus inside an .m4b, usually about 70% smaller with no audible loss for narration. Multi-file books are merged into one file with one chapter per part. Everything is written to a staging folder: originals are only read, never changed or deleted, and nothing is moved into your library. Putting converted books in place is a later step that is not built yet.
    

      
    
        
        
        
        
      
    

      
    Encoder settings
    
      
    
        
        
        
        
        
        
        
        
        
      
    

      
    
        What always happens (not configurable)
        
      
          
    • VBR on (unconstrained): silence and pauses get almost no bits, speech gets more. Checked on real output: packets range from 8 to 240 bytes.
      • 
          
    • Compression level 10 (libopus maximum quality per bit; the ffmpeg default).
      • 
          
    • Mono only when nothing is lost: the whole-book null test above. Mixed books keep stereo.
      • 
          
    • One file per book: multi-file books are merged, one chapter per part, offsets from the decoded length of each part (container durations of MP3 are estimates). A self-test merges a synthetic 12-part book first; if this ffmpeg writes wrong merged chapters, multi-file books are skipped.
      • 
          
    • Chapters kept: out-of-order MP3 chapter frames are sorted, and chapters the MP4 muxer collapses are remuxed back in.
      • 
          
    • Tags and cover kept: M4B sources copy every tag verbatim (including custom atoms); other sources map tags through ffmpeg and embed the cover (folder image first).
      • 
          
    • Fast start: the index (moov) is written before the audio, so players and Audiobookshelf can read tags without reading the whole file.
      • 
          
    • Verified before it counts: codec, channels, duration (within 0.5 s), chapter count, offsets and titles, every tag, cover, atom order, and a full decode of the audio.
      • 
          
    • Sidecar: the book's libraforge.json is carried over with an opus_conversion block (settings, mono test result, source fingerprints, verify results). A book already converted with the same settings is skipped next time.
      •

        Test findings behind these defaults
        
    
          
    Library run (Oct to Nov 2026). About 3,500 books, 43,000 hours: 1,950 GB to 626 GB (-68%). Every book was verified before its original was replaced. Sources at or below 48 kbps (31 books) were left alone.
    
          
    Hybrid vs CELT-only, same 5 minutes of a 127 kbps stereo AAC narration (identical channels, so encoded mono). Band level compared with the source; 0 dB = unchanged, about 1 dB is the smallest change most people hear.

    • Raising the bitrate does not fix hybrid mode's dip (still there at 48k); only the switch to CELT does. CELT-only at 32k is the same size as hybrid at 32k.
      • 
            
    • Caveat: CELT codes each band's energy explicitly, so this measurement flatters it. It is a strong sign, not proof; in a blind listen the two sounded alike, and the dip was the only measurable difference.
      • 
            
    • Stereo to mono lost nothing on that book: left and right were bit-identical (side signal at -200 dB).
      • 
            
    • VBR: file size follows the bitrate, not the mode. VOIP mode does not make files smaller; projects that report big savings with it are mostly using 24 kbps.
      • 
            
    • Encoder: the bundled ffmpeg 9 build ships a libopus newer than the 1.6.1 release, and gave about 7% smaller files than ffmpeg 5 at the same settings.
      • 
            
    • Speed: about 175x real time per machine with turbo on, 366x with Intel turbo off (cooler, so more parallel books); a 12-hour book takes about 5 minutes on one core.
      • 
            
    • Lossy to lossy: the output can only lose detail relative to the source, so never transcode an Opus book again; the source cap and the leave-alone threshold exist for this reason.
